# Personal Agent

Персональный агент в Telegram. Каждый пользователь получает собственный профиль после `/start`: задачи, заметки, память обсуждений, планы, настройки и подключения календарей. Кнопка меню «Мой агент» открывает Telegram Mini App. Сервер проверяет подпись Telegram, а не доверяет переданному в URL user ID.

## Навыки

| Навык                   | Что делает                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Память обсуждений       | Извлекает важные решения с цитатами и номерами сообщений; ищет по всей сохранённой памяти                                  |
| Встречи                 | Выделяет договорённости, уточняет неоднозначность, создаёт связанные события с местом и описанием; переносит и отменяет их |
| Планы                   | Собирает дела на месяц/год из обсуждений; сохраняет явно сообщённый результат                                              |
| История                 | Хранит изменения, предыдущий статус, описание результата и источники                                                       |
| Сообщения и напоминания | Пишет в личку, напоминает о делах и отправляет сообщения по прямым поручениям пользователя                                 |

Навыки — ограниченные обработчики в `src/skills.js`; отдельные постоянно работающие LLM-процессы не запускаются. Оркестратор маршрутизирует личные запросы, сообщения групп и фоновые задания. Запросы к модели выполняются по необходимости с ограничением шагов и размера контекста.

## Как пользоваться

1. Открыть личный чат и нажать `/start`. Создаётся отдельный профиль; незарегистрированному пользователю бот предлагает сначала познакомиться через `/start`.
2. Открыть «Мой агент» в меню или `/settings`. Настроить навыки, часовой пояс, стиль ответов, сообщения и срок хранения переписки. Подключить Google/Яндекс, выбрать календарь встреч.
3. Добавить бота в группу. Если его добавляет зарегистрированный администратор, обработка включается с публичным уведомлением. Иначе зарегистрированный администратор включает `/track`. `/untrack` отключает его профиль от чата.
4. Для получения обычных сообщений сделать бота администратором или отключить privacy mode в BotFather. Бот не получает сообщения других ботов и старую историю через Bot API.
5. В группе обращаться через `@имя_бота`, ответ на его сообщение или `/ask`. `/plan` и `/history` показывают только данные текущей группы. Личные инструменты и подключения в группе недоступны.
6. В личке можно спросить «Какой план на апрель 2027?» или «Что мы решили по релизу?». Модель может искать старые записи по периоду, виду и тексту, а не ограничиваться последними сообщениями.

Чат привязывается к профилю администратора. Для записи встречи в его календарь нужно его согласие в обсуждении, включённый навык встреч, разрешение на запись и выбранный календарь. Отдельная проверка сопоставляет действие с цитатами. Неясные даты и предложения без согласия не должны становиться подтверждёнными событиями. Это AI-анализ, а не гарантия понимания любой формулировки: существенные встречи нужно проверять.

Бот обновляет только события, которые создал сам и связал с записью обсуждения. Изменения в обсуждении учитываются по новым и отредактированным сообщениям. Непрерывного опроса календаря на внешние изменения пока нет. Массовые приглашения участникам не отправляются.

Дела не закрываются по наступлении срока. Сообщите результат обычным текстом, в исходном обсуждении либо используйте `/done ID Описание результата` в личке. Агент фиксирует результат; сам по себе не выполняет произвольные реальные дела вроде покупки билетов или отправки приложения в магазин.

### Команды

`/start`, `/settings`, `/skills`, `/tasks`, `/notes`, `/reminders`, `/plan`, `/history`, `/done`, `/contacts`, `/outbox`, `/approve ID`, `/cancel ID`, `/alias CHAT_ID Имя`, `/clearhistory`, `/cancelimport`, `/stop`.

`/stop` приостанавливает профиль, обработку групп и уведомления. `/start` возобновляет его без удаления данных. Получатель сообщений должен сам запустить бота; отправка неизвестному человеку только по username невозможна. Режим «Сначала черновик» доступен в настройках. Неопределённый статус сетевой доставки не приводит к автоматической повторной отправке.

## Старая переписка

В Telegram Desktop откройте нужный чат → меню → «Экспорт истории чата» → JSON (без медиа). Отправьте боту в личку файл `result.json`, максимум 5 МБ и 10000 сообщений. Для большого чата экспортируйте части по датам.

Импорт разбирается в фоне пакетами по 40 сообщений. Записи получают отдельный источник `archive:…`. Сохраняются решения, планы, встречи и история в рамках включённых навыков; после обработки сырой архив не записывается на диск. В оперативной памяти кэшируется только один экспорт, прогресс хранится в SQLite. `/cancelimport` прекращает дальнейший разбор.

Исторические сообщения никогда не создают и не изменяют календарные события и не запускают напоминания. Архив пока не объединяется автоматически с живым чатом: его планы доступны в личном профиле. Автоматическая выгрузка старой переписки недоступна обычному Telegram Bot API; интеграции личного аккаунта здесь нет.

## Хранение и изоляция

- `data/personal.sqlite`: регистрация профилей, подписки на группы, технический offset.
- `data/profiles/<telegram-id>/personal.sqlite`: отдельные личные данные и настройки.
- `data/profiles/<telegram-id>/vault.json`: OAuth-токены и пароли CalDAV под AES-256-GCM.
- Сырой текст: максимум 80 последних сообщений на обсуждение, до 32 обсуждений с сырым текстом на профиль, TTL 7/30/90 дней. До 8 подключённых групп на профиль.
- До 2000 важных записей и 5000 изменений истории; при заполнении новые записи останавливаются, важные данные не удаляются молча. Заметки/задачи/напоминания также имеют лимиты.
- SQLite ограничена 64 МиБ на профиль. WAL автоматически checkpoint-ится; технические списки очищаются. По умолчанию до 32 профилей (`MAX_PROFILES`, максимум 100).
- Решения и история выгружаются кнопкой в Mini App. Автоматического безвозвратного удаления профиля пока нет; `/stop` только приостанавливает.
- 20 сообщений в личном контексте LLM; фоновые обсуждения разбираются после 15 секунд тишины. Поиск по памяти имеет страницы и явно сообщает неполноту.

SQLite содержит личные данные в открытом виде на сервере, поэтому права каталога, шифрование диска и резервные копии важны. Только секреты подключений зашифрованы приложением. Текст обсуждений передаётся настроенному LLM-провайдеру для анализа. Чужая переписка считается данными, а не командами; техническая изоляция профилей не зависит от ответа модели.

## Запуск

Node.js 24, Docker Compose. В репозиторий не попадают `.env`, `data` и `node_modules`.

```bash
cp .env.example .env
# Заполните TELEGRAM_BOT_TOKEN, LLM_API_KEY, LLM_MODEL.
# VAULT_KEY — постоянные 32 случайных байта в base64:
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
npm ci --ignore-scripts
npm test
npm start
```

Без `PUBLIC_BASE_URL` работает диалоговый бот; Mini App требует постоянный HTTPS-адрес. Токен и Telegram ID пользователей не нужно присылать разработчику: токен хранится на сервере, профили создаются через `/start`.

Для Docker сначала создайте каталог данных с UID пользователя контейнера:

```bash
mkdir -p data
sudo chown 1000:1000 data
chmod 700 data
sudo docker compose up -d --build
```

HTTP слушает порт 8092, опубликованный только на `127.0.0.1`. Поставьте reverse proxy с TLS, направьте `/app`, `/api/*`, `/oauth/*` на этот порт и задайте `PUBLIC_BASE_URL=https://ваш-адрес`. `/health` — проверка процесса. При существующем Telegram webhook приложение останавливается, не удаляя его автоматически.

При первом запуске на VPS можно использовать `python3 scripts/configure.py`: токен вводится скрыто, существующие параметры DeepSeek читаются локально из прежнего сервиса, ключи не выводятся. Скрипт создаёт `.env` с правами 600 и сохраняет существующий ключ шифрования. Изменение `VAULT_KEY` без миграции делает подключения нечитаемыми.

## Mini App и OAuth

Mini App проверяет HMAC `initData`, срок действия и зарегистрированный Telegram ID. После этого сервер выдаёт краткоживущую сессию, привязанную к профилю. Подмена `user` в URL не меняет профиль. OAuth использует одноразовые state/ticket, привязку к браузеру и PKCE для Google; токены не возвращаются в браузер или LLM.

### Google

1. Создайте OAuth application типа Web application; включите Calendar API.
2. Задайте `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` на сервере.
3. Зарегистрируйте redirect URI: `https://ваш-адрес/oauth/callback/google`.
4. В тестовом режиме добавьте нужных пользователей в test users OAuth consent screen.
5. Подключите аккаунт в настройках. По умолчанию запрашивается чтение; для записи включите разрешение и подключитесь повторно.

Авторизация открывается официальной страницей через `Telegram.WebApp.openLink`: Google запрещает OAuth в неподходящих встроенных user-agent. После входа пользователь возвращается в Mini App.

### Яндекс

1. Создайте OAuth application в Яндекс ID, настройте необходимые права и callback `https://ваш-адрес/oauth/callback/yandex`.
2. Задайте `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
3. Войдите через настройки. Вход в Яндекс ID отдельно не означает доступ к календарю: сервис проверяет CalDAV.
4. Если OAuth-токен не даёт CalDAV-доступ, создайте пароль приложения «Календарь» в Яндекс ID и введите его в отдельной форме Mini App. Основной пароль аккаунта вводить нельзя.

Поддержка OAuth для CalDAV зависит от прав приложения/аккаунта; доступ не обещается до успешной проверки. Удаление подключения удаляет секрет у агента, но отзыв разрешения у провайдера выполняется в его настройках.

## Проверка

`npm test` проверяет границы доступа, изоляцию профилей и Mini App, подписи Telegram, OAuth, шифрование, ограничение памяти, импорт, поиск старых планов, историю выполнения, жизненный цикл встречи, дедупликацию и неопределённую доставку. Сетевые интеграции в тестах заменены контролируемыми адаптерами. Реальная авторизация Google/Яндекс и отправка сообщений требуют ваших ключей и HTTPS; без них end-to-end проверка не выполнена.
